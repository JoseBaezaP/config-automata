Capacidad por hora:
- ST37 - Rediseño total de capacity
Como Desarrollador fullstack
Quiero rediseñar completamente el módulo de capacity por hora
Para soportar la nueva estructura de days + hours con lógica automática de time_slots
Prioridad: MUST
Criterios de aceptación:
1. Rediseño total de capacity implementado
2. Nueva estructura days[] + hours[] en lugar de capacity array
3. Cada day tiene hours[] con from, to, quantity, shippingFee
4. Lógica automática para generar time_slot siguiente
5. Botón para añadir nuevo time_slot
6. Import/export masivo de time_slots
7. Eliminar input "Maximo de ordenes por hora"
8. Eliminar sección de costo de envío
Nota: La lógica para calcular "to" es: if from is 9:00, then to is 9:59

- ST38 - Lógica automática para time_slots
Como Usuario final
Quiero que el sistema calcule automáticamente el siguiente time_slot
Para no tener que ingresar los rangos de horas manualmente
Prioridad: SHOULD
Criterios de aceptación:
1. Si el último time_slot es de 9:00-9:59, el siguiente debe ser 10:00-10:59
2. El sistema debe pre-calcular el valor de "from" al añadir un nuevo slot
3. El valor de "to" debe ser el último minuto de la hora "from"

- ST39 - Import/export de time_slots
Como Administrador de tiendas
Quiero cargar de forma masiva varios time_slots desde un template
Para no tener que crear cada time_slot manualmente
Prioridad: SHOULD
Criterios de aceptación:
1. Botón para descargar template de time_slots
2. Botón para importar time_slots desde archivo Excel o CSV
3. Avisar al usuario que todos los datos existentes se sustituirán por los nuevos
4. Confirmar con el usuario antes de hacer la conversión a JSON
5. Validar formato del template antes de importar
